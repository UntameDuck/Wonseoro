# admin-web — 입학처 콘솔

근거: 기술설계서 v1.1 §A14(설정 거버넌스) · §B16·§B18(대조·예외) · §A11·§C6(증적) · §A15(보존기간) · §B17(마감 연장)

## 화면

| 경로 | 하는 일 |
|---|---|
| `/` | 지금 처리할 일 — 승인 대기 설정·마감 정책, 미해결 불일치, 지금 적용 중인 마감 |
| `/config` | 설정 승인 — 전형 양식·서류·보존정책 변경 초안을 만들고, **무엇이 바뀌는지 확인하고** 두 명이 승인한다. 깨진 양식은 초안 단계에서 거절된다 |
| `/deadline` | 마감 · 연장 — 입학처 결정에 따른 마감 연장을 기록하고 적용한다. 적용 기록은 서명되어 고칠 수 없다 |
| `/reconciliation` | 대조 · 예외 — 결제·접수·통합 조회 반영이 어긋난 건만 모아 보고, 사유와 함께 해소한다 |
| `/evidence` | 증적 조회 — 한 원서의 접수 과정을 재구성한다. 조회 사실이 기록된다 |
| `/retention` | 보존기간 — 데이터 종류별 파기 계획을 본다. 아무것도 지우지 않는다 |

## 이 콘솔이 하지 않는 일

운영자가 이 콘솔로 할 수 없는 일을 할 수 있다고 믿으면, 그 믿음이 사고가 된다. 전에는 콘솔 첫 화면에 이 설명을 두었다.
지금은 각 화면이 할 수 없는 행동을 버튼 옆에 이유와 함께 말하고, 전체 원칙은 여기 둔다(T-M5-50 — 운영 매뉴얼 T-M6-14 로 옮길 내용).

- **혼자서 마감시각·설정을 바꾸지 않는다** — 작성자가 아닌 두 명의 승인이 필요하다
- **데이터를 직접 고치지 않는다** — 모든 보정은 사유와 함께 기록된다. 결제·접수 상태를 화면에서 바꾸는 경로는 없다
- **마감 연장을 결정하지 않는다** — 입학처 결정 문서번호 없이는 연장을 만들 수 없다

## 신원

- 브라우저는 admission-api 를 직접 부르지 않는다. 콘솔 서버(`/api/admin/*`)가 운영 토큰을 붙여 넘긴다 — 토큰은 브라우저에 없다
- 담당자 ID 입력칸은 **개발 서버(`next dev`)에서만** 그린다. 입력한 이름이 그대로 승인·적용 기록에 남고 증명된 신원이 아니다.
  운영 빌드에는 들어가지 않고(`ADMIN_DEV_OPERATOR=1` 로 빌드하면 멈춘다), 담당자 쿠키도 믿지 않는다(T-M5-53).
  관리자 SSO·MFA(T-M5-10)가 이 자리를 맡는다. 그 전에는 운영에서 콘솔이 동작을 거부한다
