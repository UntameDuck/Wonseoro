# frontend — 지원자 웹

담당: 권민준 · 근거: 기술설계서 v1.0 §12, v1.1 §07

## 6단계 흐름 (v1.1 §07 — canonical)

```
1. 공통정보  2. 대학·전형  3. 추가정보  4. 서류  5. 검토·결제  6. 최종제출  → 완료
```

> 개발보고서(PDF)와 v1.0 §12.1은 각각 5단계 / 10개 IA로 적혀 있으나,
> **KRDS 단계 표시기 권장 범위에 맞춘 v1.1 §07의 6단계를 기준으로 한다.**

## 화면 원칙 (타협 불가)

- Breadcrumb + Step Indicator 상시 노출
- **서버 기준** 마감시각·남은시간 표시 (브라우저 시간 사용 금지)
- 자동저장 상태를 항상 텍스트로: `저장 중` / `저장 완료 17:42:13` / `저장 실패 — 다시 시도`
- 오류는 페이지 상단 Error Summary + 해당 필드 인접 메시지를 **동시에**
- Label을 Placeholder로 대체하지 않는다
- 색상만으로 상태를 표현하지 않는다 (아이콘 + 텍스트 병행)
- 중요 결과를 Toast만으로 알리지 않는다. 화면에 지속적으로 남긴다
- Drag&Drop만 제공하지 않는다. 파일 선택 버튼을 항상 함께 제공
- Modal은 최종제출처럼 복구 불가능한 동작에만
- Validation 실패해도 사용자가 입력한 유효 필드는 유지

## 장애 UX (v1.1 §07)

마지막 저장시각과 **현재 서버가 확인한 상태**를 보여주고, 처음부터 다시 하도록 요구하지 않는다.
중복 제출을 반복하지 않도록 요청번호와 상태 재조회 버튼을 제공한다.
중앙 Sync 지연은 접수완료 여부와 **분리해서** 표시한다.

## 자동저장 구현 규칙 (v1.1 §10)

- 15~30초 Debounce 또는 의미 있는 변경 시 저장
- `PATCH` + `If-Match`/ETag
- 동일 값 반복 저장 억제
- 접속 끊기면 클라이언트 임시 큐 → 재연결 시 **서버 상태부터 조회**
- FINALIZED 이후 Draft 수정 API 호출 금지

## 접근성 인수 기준 (KWCAG 2.2)

- 키보드만으로 전체 접수 완료 가능
- Visible Focus, Focus Order 보장
- Screen Reader로 Label/Error/Step/Status 전달
- 200% 확대에서 기능 손실 없음
- 모바일 320 CSS px 대응
- Session Timeout 사전 경고 + 연장 옵션
- CAPTCHA 사용 시 접근 가능한 대체수단 제공
