# 제출 문서(개발보고서 PDF) 정정 목록 — T-M0-08

> 작성: 2026-09-30. 제출한 개발보고서 PDF 원본은 저장소에 없다. 이 문서는 **정정할 곳과 바꿀 문구**만 모은다 —
> 제출처가 정정본·정오표를 받는 방식에 맞춰 사람이 반영한다. 반영하면 불일치 대장 D-2·D-3 의 "PDF 반영" 을 `✅ (날짜)` 로 바꾼다.

## 정오표

| # | 대장 | PDF 의 현재 서술 | 바른 서술 | 근거 |
|---|---|---|---|---|
| 1 | D-3 | 백엔드 런타임 "Java LTS + Spring Boot 계열" (팀 기술 스택·설계 서술) | **NestJS + TypeScript (Node.js LTS)**, PostgreSQL. 트랜잭션·Outbox·관측성·장기지원 런타임이라는 요구는 그대로 충족한다 | ADR-0001 · 노션 v1.0 §4 (2026-09-27 반영) |
| 2 | D-2 | 지원자 흐름 **5단계** | **6단계** — 공통정보 → 대학·전형 → 추가정보 → 서류 → 검토·결제 → 최종제출(→ 완료) | 노션 v1.1 §07 · v1.0 §12.1·§12.2 (2026-09-27 반영) |
| 3 | D-42 | (PDF 가 "결제 후 최종제출을 따로 해야 접수" 로 적었다면) | **결제가 확인되면 서버가 바로 접수한다.** 결제창은 지금 접수할 수 있는 원서에만 열리고, 결제 후에는 수정·취소가 불가능하다고 결제 전에 알린다 | 노션 §01 §A4·§B4 · §07 (2026-09-27 반영) |

3번은 PDF 에 해당 서술이 있을 때만 정정한다 — 대장에는 노션·와이어프레임과의 차이만 기록돼 있다.

## 정정문 예시 (정오표 제출용)

> 개발보고서의 백엔드 기술 스택 표기 "Java LTS + Spring Boot" 를 "NestJS + TypeScript(Node.js LTS)" 로 정정합니다.
> 설계서가 요구하는 ACID 트랜잭션·Transactional Outbox·관측성·장기지원 런타임 요건은 변경 없이 충족하며,
> 선택 근거는 저장소 `docs/adr/ADR-0001` 에 있습니다. 또한 지원자 흐름을 5단계에서 KRDS 단계 표시기 권장 범위에 맞춘
> 6단계(공통정보·대학·전형·추가정보·서류·검토·결제·최종제출)로 정정합니다.
