# ADR-0009 — 퍼즐형 CAPTCHA 를 쓰지 않는다. 한도에 걸린 사람에게는 시각·재시도·문의·재인증 경로를 준다

- 상태: 채택
- 날짜: 2026-10-01
- 관련: T-M5-46, ADR-0007(지원자 단위 Adaptive Throttling), 기술설계서 v1.1 §01 B6·§07 「접근성」, T-M5-02

## 맥락

설계는 "CAPTCHA 는 고위험 요청에만, 접근 가능한 대체수단과 함께"(§01 B6), "CAPTCHA 대체수단"(§07 접근성)을 요구한다.
지금 원서로에는 CAPTCHA 가 없다. 자동화 남용은 ADR-0007 의 지원자 단위 한도·위험점수가 막고, 막힌 요청은
`429 RATE_LIMITED` + `Retry-After` 로 끝난다. 그런데 화면은 이 경우를 다루지 못했다 — 버튼 동작이 429 를 받으면
**화면 전체가 장애 안내로 바뀌었고**, 문구는 "잠시 후 자동으로 다시 시도합니다" 였지만 **아무것도 다시 보내지 않았다.**
잘못 막힌 사람(공용 PC·같은 반 친구들과 같은 시각에 몰린 정상 수험생)이 지나갈 길이 사실상 없었다.

## 결정

1. **퍼즐형 CAPTCHA(그림 고르기·글자 읽기·소리 듣기·끌기)를 두지 않는다.** 시각·청각·운동 장애가 있는 수험생에게
   그대로 장벽이고, 대체 수단(음성 CAPTCHA 등)도 스크린리더 사용자에게 어렵다. 한도의 키가 IP 가 아니라 인증된 지원자라서
   (ADR-0007) "이 요청이 사람인가" 를 묻는 것으로 얻는 것도 적다 — 운영에서는 검증된 계정 하나가 쓸 수 있는 양이 이미 묶인다.
2. 한도에 걸린 사람의 길은 넷이다. 모두 키보드·스크린리더로 갈 수 있다.
   - **기다림** — 화면은 그대로 두고 "17:42:13부터 다시 누를 수 있습니다" 를 글로 알린다(안내가 포커스를 받는다).
     누른 버튼만 그때까지 쉬고, 시각이 되면 같은 알림 영역이 "이제 다시 시도할 수 있습니다" 로 바뀌며 버튼이 열린다.
     몇 초~몇 분이다(순간 몰림은 초 단위, 위험점수는 반감기 5분).
   - **자동 재시도** — 자동저장은 서버가 준 시간 뒤에 한 번 저절로 다시 보낸다(이미 있었다). 결제·접수 같은 버튼 동작은
     저절로 다시 보내지 않는다 — 그래서 "자동으로 다시 시도" 라는 문구를 버튼 동작에서 뺐다.
   - **문의** — 안내에 요청번호를 함께 보인다. 입학처는 그 번호로 로그를 찾는다.
   - **본인확인 다시 하기(step-up)** — 위험점수로 막혔을 때 바로 푸는 길. 본인확인(T-M5-02)이 붙을 때 함께 만든다 —
     접근성 기준을 통과한 본인확인 수단이 "사람 확인" 을 대신한다. 그 전까지는 위의 셋이다.
3. 최종제출(결제 확인 뒤 자동 접수)은 지금처럼 정상 세션에서 막지 않는다(ADR-0007 결정 4).

## 결과

- 접수 홈("원서 작성 시작")·원서 화면(검토 단계로·결제·취소)·서류 업로드가 429 를 같은 방식으로 다룬다.
  시험 `tests/a11y/rate-limit.mjs` — 검증 응답 한 번을 429(Retry-After 6초)로 바꿔, 화면 유지·안내 포커스·시각·요청번호·
  버튼 쉼·6초 뒤 같은 알림 영역의 문구 바뀜·버튼 열림·키보드로 이어 감·퍼즐 없음을 확인했다(축소 환경).
- 위험점수로 막힌 정상 사용자는 최대 몇 분을 기다린다. 마감 직전이면 아플 수 있다 — step-up 본인확인이 그 시간을 없앤다.
  그래서 T-M5-02 인수기준에 "위험 차단을 본인확인으로 해제" 를 더한다.
- 나중에 CAPTCHA 가 꼭 필요해지면(예: 익명 공개 조회 남용) 화면이 아니라 Edge/WAF 의 보이지 않는 검사(작업 증명 등)로 하고,
  이 ADR 을 바꾼다.
