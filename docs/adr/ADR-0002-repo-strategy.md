# ADR-0002. 단일 저장소 + 내부 강분리

- 상태: 채택 (2026-09-22)

## 맥락
FE/BE를 저장소 수준에서 분리할지 검토했다. 역할 분담이 명확하고(송리안=Core, 권민준=Web), 배포 대상도 다르다(대학 K-PaaS vs 중앙 Edge).

## 결정
**저장소는 하나로 두고, 개발·CI·배포만 분리한다.**

## 근거
- 이 제품의 핵심 자산은 API 계약·Event Schema·상태머신 정의다. 저장소를 쪼개면 즉시 두 벌이 되고, 2인 팀에는 드리프트를 잡을 여력이 없다.
- 기술설계서 v1.1 `A5(대학별 커스터마이징으로 표준 붕괴)`, `A16(Breaking Change)`이 지적한 위험과 같은 축이다.
- 저장소 2개는 PR·리뷰·릴리스 조율 비용을 2배로 만든다.

## 분리는 이렇게 확보한다
- `apps/*` 간 직접 import 금지. 반드시 `packages/contracts` 경유.
- GitHub Actions `paths:` 필터로 앱별 독립 잡.
- Dockerfile·Helm 차트는 앱마다 독립.
- 접수기간 Freeze도 앱 단위로 적용.

## 재검토 시점
대학 Pilot 3곳 초과 + Data Plane 코드를 대학 정보화부서에 인계해야 할 때.
