> 기준: 노션 §07 「접근성」 — 키보드만으로 전체 접수, Visible Focus, Screen Reader Label/Error/Step/Status, 200% 확대,

## 어떻게 시험하나

사람이 하는 검사(T-M5-48, 실제 스크린리더·보조기기)는 사람의 몫이다. 여기서는 **매번 다시 돌릴 수 있는 자동 시험**으로 인수기준을 확인한다.
설치할 것은 없다 — 화면 캡처와 같이 이 PC 의 Chrome(또는 Edge)을 헤드리스로 띄워 DevTools 프로토콜로 조작한다.

| 시험 | 명령 | 무엇을 하나 |
|---|---|---|
| 키보드 완주 | `npm run test:a11y:keyboard -- --width=1280` | 마우스 없이 접수 홈 → 공통원서(오류 요약 → 칸 이동 포함) → 원서 1~6단계(검증 오류 → 칸 이동, 서류 파일 대화상자, 결제 전 확인 체크) → 접수증. 요소를 `click()` 하지 않고 Tab·Shift+Tab·Enter·Space 키 이벤트만 보낸다. 지나간 모든 자리의 포커스 표시·순서와 화면 전환 뒤 포커스 자리를 본다 |
| 전 화면 포커스 | `npm run test:a11y:focus -- applicant` · `-- admin` | 화면(상태)마다 문서 처음부터 Tab 으로 한 바퀴. 포커스 표시(테두리 2px 이상·`:focus-visible`), 표시와 배경의 명암비 3:1, 읽는 순서, 갇힘, **보이는데 Tab 으로 닿지 않는 것**, tabindex 양수. 같은 화면에서 **접근성 트리**(브라우저가 스크린리더에 넘기는 정보)도 본다 — 아래 |
| 스크린리더 재료 | 위 둘에 들어 있다(`tests/a11y/helpers/ax.mjs`) | 이름 없는 칸·버튼·링크, 오류 칸이 "올바르지 않음"·오류 문장을 설명으로 갖는지, 단계 표시의 현재 단계 하나, 화면 제목, 큰 제목(h1) 하나, 알림 영역 안의 카운트다운. Tab 자리마다 **스크린리더가 읽을 대본**(역할·이름·필수·오류·설명)을 결과에 남긴다 — 사람이 듣는 검사(T-M5-48)의 대조표 |
| 확대·좁은 화면 | 위 둘에 `--width=640`(1280 화면의 브라우저 200% 확대와 같은 CSS 폭)·`--width=320`·`--text-zoom=2`(글자만 200%) | 같은 시험을 그 조건으로 돈다. 화면마다 **가로 스크롤**(문서가 화면보다 넓은가 — 넘치는 요소 이름까지)과 **잘린 글**(넘침 숨김 칸 안에서 글이 잘리는가)을 본다. 데이터 표는 제 영역 안에서만 옆으로 움직이면 된다(KWCAG 재배치 예외) |
| 세션 만료 경고 | `npm run test:a11y:session` | 세션 만료 시각만 앞당긴다(30분을 기다리지 않는다). 입력 → 경고·경고 순간 저장 → 대화상자 포커스 가둠 → Esc 연장 → 다시 경고 → "계속 이용하기" → 더 입력하고 만료 → 마지막 입력 저장·닫을 수 없는 종료 안내·세션 지움 |
| 한도 해제 경로 | `npm run test:a11y:rate-limit` | 검증 응답 한 번을 429(Retry-After 6초)로 바꿔, 퍼즐 없이 키보드·스크린리더로 지나가는지 본다 |
| 휴대전화(터치) | `npm run test:a11y:keyboard -- --input=touch --width=390 --height=844` | Android Chrome 흉내(손가락 입력·모바일 브라우저 이름·고밀도 화면). Tab 대신 이름으로 찾아 탭해서 같은 접수 흐름을 끝까지. **탭한 대상의 크기**(체크는 감싼 라벨)를 잰다 |
| 다른 브라우저 | 모든 시험에 `--browser=edge` 또는 환경변수 `CHROME=<실행 파일>` | 같은 시험을 Edge 로 |
| 마감 경고 알림 | `npm run test:a11y:deadline` | 서버 시각 응답만 가로채 남은 10분 3초를 만든다. 8초 동안 화면 숫자는 매초 바뀌고, 스크린리더 알림은 경고 단계가 바뀔 때만인지 본다 |

서버는 화면 캡처와 같은 전용 DB(`ui-shots-pg` :5497)·전용 포트다 — 띄우는 법은 [screenshots/README.md 「다시 찍기」](screenshots/README.md#다시-찍기) 1~3.
키보드 완주는 실행마다 새 지원자를 DB 에 넣는다. 콘솔 점검(`admin`)은 콘솔(`shots-admin`)이 떠 있어야 하고, `prepare.sh config` 로 설정 초안을 만들어 두면 검토 화면까지 본다.
결과는 `tests/a11y/results/` 에 JSON 으로 남는다(마감 경고 알림은 화면에 찍기만 한다). **모두 축소 환경(로컬 개발 서버·Mock PG·Mock 검사 엔진) 결과다.**

화면이 쓰는 웹 기능 가운데 가장 늦게 들어온 것이 기준이다. 그보다 옛 브라우저는 일부 기능(세션 경고 대화상자 등)이 동작하지 않는다.
