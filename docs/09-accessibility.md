> 작성: 2026-10-01 · 태스크 [M5 「접근성」 T-M5-40 ~ 47](milestones/M5-reliability-security.md#접근성-권민준)
> 기준: 노션 §07 「접근성」 — 키보드만으로 전체 접수, Visible Focus, Screen Reader Label/Error/Step/Status, 200% 확대,
> 모바일 320 CSS px, Session Timeout 사전경고, CAPTCHA 대체수단. 수치 기준이 없는 항목은 KWCAG 2.2(= WCAG 2.2 AA 대응)를 따른다.
> 화면 제품화(T-M5-50~56, [08](08-ui-production-readiness.md))가 끝난 같은 화면 위에서 한다. **디자인(배치·색·컴포넌트 모양)은 바꾸지 않는다.**

## 어떻게 시험하나

사람이 하는 검사(T-M5-48, 실제 스크린리더·보조기기)는 사람의 몫이다. 여기서는 **매번 다시 돌릴 수 있는 자동 시험**으로 인수기준을 확인한다.
설치할 것은 없다 — 화면 캡처와 같이 이 PC 의 Chrome(또는 Edge)을 헤드리스로 띄워 DevTools 프로토콜로 조작한다.

| 시험 | 명령 | 무엇을 하나 |
|---|---|---|
| 키보드 완주 | `npm run test:a11y:keyboard -- --width=1280` | 마우스 없이 접수 홈 → 공통원서(오류 요약 → 칸 이동 포함) → 원서 1~6단계(검증 오류 → 칸 이동, 서류 파일 대화상자, 결제 전 확인 체크) → 접수증. 요소를 `click()` 하지 않고 Tab·Shift+Tab·Enter·Space 키 이벤트만 보낸다. 지나간 모든 자리의 포커스 표시·순서와 화면 전환 뒤 포커스 자리를 본다 |
| 전 화면 포커스 | `npm run test:a11y:focus -- applicant` · `-- admin` | 화면(상태)마다 문서 처음부터 Tab 으로 한 바퀴. 포커스 표시(테두리 2px 이상·`:focus-visible`), 표시와 배경의 명암비 3:1, 읽는 순서, 갇힘, **보이는데 Tab 으로 닿지 않는 것**, tabindex 양수 |

서버는 화면 캡처와 같은 전용 DB(`ui-shots-pg` :5497)·전용 포트다 — 띄우는 법은 [screenshots/README.md 「다시 찍기」](screenshots/README.md#다시-찍기) 1~3.
키보드 완주는 실행마다 새 지원자를 DB 에 넣는다. 콘솔 점검(`admin`)은 콘솔(`shots-admin`)이 떠 있어야 하고, `prepare.sh config` 로 설정 초안을 만들어 두면 검토 화면까지 본다.
결과는 `tests/a11y/results/` 에 JSON 으로 남는다. **모두 축소 환경(로컬 개발 서버·Mock PG·Mock 검사 엔진) 결과다.**
