# 대학 온보딩 안내 — 입학처·정보화부서용

> 기준일: 2026-10-03 · 태스크 **T-M6-14** · 읽는 사람: 대학 입학처(전형·일정·고지)와 정보화부서(인프라·계정·보안)
>
> 원서로는 대학마다 **자기 서버(Data Plane)** 에서 접수를 받는다. 접수 원본은 대학 DB 에 있고, 중앙에는 개인정보 없는 요약만 간다.
> 그래서 대학이 준비할 것은 "설정" 과 "자기 인프라" 두 가지다. 프로그램을 고칠 일은 없다 — 같은 프로그램·같은 배포 묶음(차트)을 대학 값만 바꿔 쓴다.

## 1. 한눈에 — 누가 무엇을

|---|---|---|---|

## 2. 입학처 — 설정

- **모집(주기)·전형·모집단위** — 운영 콘솔에서 설정 초안을 만든다. 초안은 바로 적용되지 않는다 — 작성자가 아닌 **두 사람이 승인**해야 적용된다. 적용된 설정은 바뀌지 않고, 바꾸려면 새 판을 만든다(Diff 로 무엇이 달라지는지 보인다)
- **원서 양식** — 전형마다 추가 항목(예: 내신 성적, 학적 변동 사항). **자기소개서는 받지 않는다**(고등교육법 시행령 제35조 — 설정 검사가 경고한다). 공통원서(출신 고교·졸업 연도·이메일·휴대전화)에서 가져올 항목은 "공통원서에서 가져옴" 으로 표시한다 — 지원자가 이미 쓴 값을 동의를 받아 가져오고, 동의가 없으면 비워 둔다
  - 항목마다 화면에 보일 이름이 있어야 한다(없으면 설정 검사가 거절)
  - 주민번호 같은 고유식별정보는 근거 없이 넣지 않는다(문서 10 §5.3)
- **제출 서류** — 전형마다 필수·선택 서류와 이름. 받는 형식은 PDF·JPG·PNG 뿐이다(크기 PDF 10MB, 그림 5MB). 서류는 올리는 즉시 악성코드 검사를 거치고, 자바스크립트가 든 PDF·첨부 파일이 든 PDF 는 받지 않는다
  - **민감정보 서류(`sensitiveDocuments`)** — 장애인 증명서·진단서·입원확인서처럼 장애·건강 정보를 담은 서류는 서류 종류마다 **별도 동의 코드**를 지정하고 그 문안을 원서 동의(`consents`)에 **필수 아님**으로 넣는다(개인정보 보호법 제23조). 지원자는 그 서류 바로 위에서 동의한 뒤에만 올릴 수 있고, 서류가 있는 동안 동의를 거두면 접수할 수 없다. 이름에 장애·진단·입원·건강 등이 보이는데 지정하지 않으면 설정 검사가 경고하고, 문안 없는 동의를 가리키면 거절한다. 기회균형 서류(수급·한부모 등)를 같은 틀로 다룰지는 대학이 정한다(D-85)
  - **정보주체 권리 요청** — 지원자가 원서에서 보낸 열람·정정·삭제·처리정지 요청은 콘솔 「권리 요청」 큐에 쌓인다. 받은 날부터 10일 안에 회신하고, 정정·삭제 자체는 대학 규정·보존 의무를 따라 입학처가 처리한다(D-84)
- **지원자 고지(`notices`)** — 개인정보 처리방침 주소·처리 위탁 공개 주소(https), 개인정보 보호책임자(또는 담당 부서·연락처), 입학처 문의처, **전형료 반환 사유·금액·방법**(고등교육법 시행령 제42조의3), **지원 제한**(`applicationRules` — 수시 지원 횟수·정시 군별 지원·수시 합격자 정시 지원 금지·이중등록 금지와 위반 시 입학 무효, 시행령 제42조·제42조의2. 접수 홈에서 원서 작성 전에 보이고 확인을 받는다, D-86). 처리방침·보호책임자·반환 안내가 빠지면 설정 검사가 경고하고, 주소가 https 가 아니면 거절한다. 화면은 바닥글(처리방침·위탁·보호책임자·문의처)과 검토·결제·접수증(반환 안내)에 그대로 보인다 — 문안은 입학처·법무가 승인한 것을 넣는다(D-80)
- **마감 정책** — 마감 시각과 판정 방식. 연장은 결정 근거(번호)와 사유가 있어야 기록된다
- **접수 몰림 대비(Peak Mode)** — 마감 전 서버를 미리 늘리는 예약을 대학 값(`peak-schedule.yaml`)으로 둔다. 예약 창 안에서는 급하지 않은 내부 작업을 멈춘다

## 3. 정보화부서 — 인프라

같은 차트(`deploy/charts/k-admission`)에 대학 값(`deploy/universities/<대학>/values.yaml`)을 더해 GitOps 로 배포한다. 서명된 이미지만 돈다.

| 항목 | 준비할 것 | 근거 |
|---|---|---|
| 클러스터 | `npm run ops:csp-preflight -- --context=<컨텍스트>` 의 필수 7개 통과 — 1.30 이상, 승인 정책 API, 기본 StorageClass, zone 2개 이상, Pod Security restricted, **NetworkPolicy 가 실제로 막을 것**, LoadBalancer | [문서 14](14-operations-automation.md) |
| PostgreSQL | 대학 전용 인스턴스(다른 대학과 같이 쓰지 않는다)·Multi-AZ·PITR. 마이그레이션 `0001`~`0008` 적용 | [infra/db/README](../infra/db/README.md) |
| Object Storage | 서류 버킷(비공개) + **감사 WORM 버킷**(Object Lock COMPLIANCE — 만들 때 켜야 한다) | D-75 |
| Vault | 대학 경로 — Transit `pii-<대학>`(원서 암호화 키), DB 역할 `admission-api-<대학>`·`break-glass-<대학>`, PKI 역할 `kadmission-<대학>-<워크로드>`(워크로드마다), Kubernetes 인증 역할 `<대학>-<워크로드>` | [문서 13 단계 4](13-security-controls-plan.md), D-71 |
| 중앙 연결 | 중앙 주소, 대학 Relay·API 의 워크로드 인증서(상호 TLS). 다른 대학 이름으로는 보낼 수 없다 | D-69 |
| 경보 | Prometheus 에 KPI 규칙·만료 경보 규칙(`expiry-rules.yaml`), 비상 역할 경보 웹훅 | T-M5-65, D-72 |
| 쓰기 세대 | 장애 전환 순서에 `promote_writer` → `WRITER_EPOCH` 배포를 넣는다. 운영은 `require_token` 을 켠다 | D-76 |

## 4. 계정과 권한

- **상담 담당(`support-agent`)** — 고객센터 상담원. 접수번호·상담 확인번호로 접수·결제 상태만 본다(원서 내용·연락처 없음), 조회마다 증적번호가 남는다. 쿠버네티스 권한 없음(D-79)
- **Kubernetes 역할 6종**(대학 네임스페이스 한정) — 조회·SRE(규모 조정·재시작만, Pod 구성은 못 바꾼다)·보안 감사·배포 계정·비상 역할(평소 꺼짐, 12시간 안의 끝나는 시각과 사유가 있어야 켜지고 매분 회수 작업이 지운다)·입학 관리자(쿠버네티스 권한 없음)
- **운영 콘솔 담당자** — 대학 로그인 서버(OIDC) + 2단계 인증(OTP). 승인 같은 중요한 작업은 5분 안에 다시 인증
- **DB 비상 접속** — Vault 비상 그룹만 15분 계정. 발급이 DB 에 남고 그 계정의 모든 문장이 로그에 남는다

## 5. 접수 전 확인 순서

1. CSP 사전 점검 통과 → 2. 차트 배포(대학 값)·마이그레이션 → 3. 설정·마감 정책 두 사람 승인 → 4. 시험 결제·본인확인 →
5. 접근성·화면 확인(같은 화면을 쓴다) → 6. 모의 접수(Shadow)·장애 훈련 → 7. 복구 검증(`npm run ops:restore-verify` — 운영은 백업에서 복구한 DB 로) → 8. 접수 시작

## 6. 접수 중·뒤

- 대학이 멈춰도 다른 대학 접수는 그대로다(축소 환경에서 확인, T-M4-42). 중앙이 멈춰도 대학 접수는 계속되고, 요약은 복구 뒤 보내진다
- 지원자 "내 원서" 는 중앙이 가명 참조로 모아 보여 준다 — 이름·연락처는 중앙에 없다
- 감사 기록은 WORM 버킷에 5년 남고, DB 와 대조해 변조를 찾는다
- 보존 기간이 지난 자료의 파기는 대학 규정·승인 절차를 따른다(파기 실행 화면은 아직 없다 — 문서 04)
